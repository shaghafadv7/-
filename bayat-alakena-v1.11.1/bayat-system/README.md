# نظام بيات الأكنة لإدارة الوحدات والحجوزات والمبيعات — v1.9.0

تطبيق Windows داخلي مستقل لإدارة المشاريع، الأدوار، النماذج، الوحدات، الأسعار، البحث المتقدم، العملاء، الحجوزات، المبيعات المرحلية، الخصومات، الدفعات، المسوقين والعمولات، التقارير المالية، ومستندات PDF بهوية الشركة وأرشيف مستندات دائم، **وتقرير المشاريع Excel**.

## ما الجديد في v1.10

- **التتبع المالي الكامل لكل دفعة**: مسار الدفعة (من دفع → لمن سُلم → أي حساب → العملية المرتبطة)،
  حالة الدفعة (مستلمة/مودعة/مرتجعة/ملغاة/معلقة)، المستلم والحساب/الخزينة، والسجل الموحد.
- **بيانات الحجز الشاملة**: سعر الوحدة (لقطة)، المسوق المرتبط (يورث للبيع)، الحساب المودع فيه.
- **إلغاء الحجز الكامل**: سجل إلغاء واسترداد (RFD) بالسبب والمرتجع والمخصوم والطريقة والمرجع
  والحساب — بلا حذف أي سجل — والوحدة تعود متاحة تلقائيًا.
- **تقرير الحجوزات الملغاة** و **تقرير الاستردادات والخصومات** (تبويبان في التقارير + PDF + فلاتر).

## ما الجديد في v1.9

- **العربون = دفعة أولى من قيمة البيع**: قيد مالي فريد (RPY) لكل دفعة حجز، يُربط تلقائيًا
  بعملية البيع عند التحويل دون تكرار، ويُحتسب في المدفوع والمتبقي.
- **تحويل الحجز إلى بيع** من صفحة الحجوزات وشاشة الوحدة.
- **تقرير المشاريع Excel** (XLSX حقيقي) بفلاتر كاملة وRTL وAutoFilter وFreeze Panes وإجماليات.
- **أمان**: Rate Limiting، CORS مقيد، إبطال الجلسات عند تغيير كلمة المرور، Idempotency،
  نسخ احتياطي مشفر، وتسجيل IP والجهاز لكل عملية.
- **صلاحيات جديدة**: تسجيل دفعة حجز، تحويل حجز لبيع، تصدير Excel، السماح بدفع زائد (59 صلاحية).
- 4 صلاحيات جديدة + إصلاح محاسبي: الإيراد المحقق لا يتجاوز قيمة العقد (الدفع الزائد لا يضخم الربح).

## الأدوار والصلاحيات

| الدور | الوصف |
|---|---|
| مدير النظام (super_admin) | كل الصلاحيات: المشاريع، الوحدات، المستخدمون، الهوية، النسخ الاحتياطي، الحذف |
| مدير عام (admin) | إدارة المشاريع والوحدات والمسوقين والمبيعات والتقارير |
| مدير مبيعات (sales_manager) | المبيعات والعمولات والمسوقين والتقارير |
| محاسب (accountant) | المبيعات المالية، الدفعات، دفعات المسوقين، التقارير المالية — بدون إدارة المستخدمين أو المشاريع أو الإعدادات |
| مسؤول حجوزات (reservations_officer) | البحث والحجز وتسجيل بيانات البيع الأساسية ومستندات الحجز — بدون بيانات مالية حساسة |
| موظف مبيعات (sales) | حجز وبيع وحداته ومتابعتها |
| مشاهدة فقط (viewer) | بحث وعرض بلا عمليات ولا مستندات |

الصلاحيات مطبقة على مستوى الـ API وقاعدة البيانات وليست إخفاء أزرار فقط.

## الجديد في v1.8.1 — النظام المالي الاحترافي لإعادة البيع

1. **إعادة البيع باسم المالك السابق**: يُلتقط تلقائيًا اسم المالك السابق وسعر الشراء الأصلي وتاريخه من الصفقة الأولى، ويظهران في بيانات العملية والسجل التاريخي وسند البيع PDF، مع المالك الجديد.
2. **رصيد العميل الذكي**: العقد − الخصومات − المدفوعات = المتبقي؛ ثلاث حالات ملونة: «مستحق على العميل» / «مستحق للعميل» (رصيد دائن عند الدفع الزائد) / «مسدد بالكامل».
3. **بند الخصومات المستقل**: جدول خصومات كامل لكل صفقة (القيمة، النوع، السبب، المعتمد، التاريخ) مع منع تجاوز إجمالي الخصومات لسعر العقد، وإلغاء مع حفظ السجل، وانعكاس فوري على السعر النهائي والمتبقي.
4. **المصروفات والمستثمر والأرباح**: تسجيل مصروفات الصفقة، وبيانات المستثمر (رأس المال)، وحساب تلقائي للربح الإجمالي وصافي الربح (بعد المصروفات والعمولات) ونسبتيهما، مع تحديث فوري عند أي تعديل.
5. **اللوحة المالية الاحترافية** داخل تفاصيل الوحدة: بطاقات ملونة (سعر العقد، الخصومات، النهائي، المدفوع، المتبقي/الرصيد، سعر إعادة البيع، المصروفات، الربح الإجمالي، صافي الربح، النسب) — ظاهرة للإدارة والمالية فقط.
6. **سجل كامل**: كل عملية (بيع، خصم، مصروف، دفعة، مستثمر) موثقة بالمستخدم والوقت في السجل التاريخي للوحدة دون فقد أي بيانات.
7. إصلاح تاريخي: ترتيب أعمدة في دالة السجل التاريخي كان يكتب معرف المستخدم في حقل التفاصيل — أُصلح وهاجس البيانات القديمة يبقى للعرض (العناوين سليمة).

## الجديد في v1.7.0 — تجديد أيقونات الواجهة

استُبدلت كل الرموز النصية القديمة (◈ ⌕ ▥ ◇ ▦ ▣ ◉ ▤ ◆ ♙ ♟ ⛁ ◎ ⚙ ☰ × ⬇ 🗄 🖨 +) بنظام أيقونات SVG خطّي موحد (37 أيقونة Minimal بأسلوب حديث): القائمة الجانبية، الرأس، أزرار كل الصفحات والعمليات (إضافة/تعديل/عرض/حذف/تصدير/حفظ/طباعة/تنزيل/دفع/صلاحيات/استعادة...)، التوستات، الحالات الفارغة، وبطاقات الأرشيف. الأيقونات تتبع لون النص تلقائيًا بحجم ومحاذاة موحدين، متناغمة مع ألوان بيات الأكنة — دون أي تغيير في التصميم أو الألوان الأساسية أو الترتيب أو الوظائف.

## الجديد في v1.6.1 — إصلاح اتجاه الجمل العربية في PDF

اكتُشف أن محرك fontkit يعكس الحروف داخل كل كلمة عربية لكنه يُبقي ترتيب الكلمات من اليسار لليمين، فكانت الجمل متعددة الكلمات تُقرأ معكوسة. أُضيفت طبقة `visualTokenOrder` — **المسؤول الوحيد عن الاتجاه** — تعكس ترتيب الكلمات/الجزر مرة واحدة عند نقاط الإخراج النهائية فقط (مع حفظ الجزر اللاتينية والأرقام والهواتف والبريد بترتيبها الداخلي)، ويبقى ترتيب الحروف لـ fontkit — **لا انعكاس مزدوج**. أُضيف اختبار اتجاه دائم (`npm run test:direction`) يتحقق من مواضع الرسمات الفعلية على مستوى الكلمة والحرف. لا تغيير في التصميم أو الجداول أو الخط أو التذييل أو البيانات أو أي وظيفة.

## الجديد في v1.6.0 — إصلاحات التقارير وPDF الأربعة

1. **العربية داخل PDF**: المحرك يمرر النص المنطقي مباشرة إلى fontkit (تشكيل + BiDi كاملان) — الحروف متصلة، ترتيب الكلمات طبيعي، والأرقام والإنجليزية والهواتف والبريد والروابط والرمز المختلط تظهر بترتيبها الصحيح، بخط Expo Arabic مضمّن.
2. **اللف التلقائي داخل الخلايا**: أي نص طويل (عناوين أعمدة، أسماء عملاء/مشاريع/مسوقين، ملاحظات) يُقسم لأسطر داخل الخلية ويُرفع ارتفاع الصف تلقائيًا — لا قص ولا إخفاء ولا تصغير مبالغ (أصغر خط ≥ 6pt)، ولا تداخل بين الصفوف.
3. **الأعمدة الكثيرة**: التوزيع الديناميكي (Landscape تلقائي للتقارير الواسعة)، ضبط عرض الأعمدة بحد أدنى منطقي، وإذا تجاوزت الأعمدة عرض الصفحة تُقسم أفقيًا على صفحات إضافية (الأعمدة 1-10 ثم 11-20...) مع تكرار رأس الجدول في كل صفحة جديدة — 100% من البيانات ظاهرة دائمًا.
4. **فوتر محجوز ومرتب**: منطقة فوتر مستقلة أسفل كل صفحة (Header → Content → Footer) بفاصل ذهبي، المحتوى لا يدخلها أبدًا، بيانات التواصل تُلف لأسطر تلقائيًا، ورقم الصفحة «صفحة i من N» محدث تلقائيًا ويتوسط الصفحة.

## الجديد في v1.5.0 — خط Expo Arabic ورمز الريال السعودي الجديد

1. **رمز الريال السعودي الرسمي** (المصدر: ساما، مجال عام) يحل محل «ر.س» في كامل النظام: الواجهة، الجداول، لوحة التحكم، التقارير، ملفات PDF والمطبوعات — صفر ظهور للاختصار القديم (مفحوص آليًا).
2. **مُنسّق مركزي موحد**: دالة `money()` واحدة في الواجهة ودالة `money()` واحدة في محرك PDF — كل المبالغ (أسعار، خصومات، مدفوع، متبقٍ، عمولات...) بالصيغة الموحدة `150,000 [الرمز]`.
3. **الرمز داخل PDF مرسوم متجهيًا** من المسار الرسمي نفسه — لا يعتمد على خط الجهاز إطلاقًا، لا يتحول لمربع ولا يختفي، ونسب أبعاده الرسمية محفوظة بلا تمديد، ويُرسم بلون النص المحيط في الجداول والترويسات والتذييلات.
4. **خط Expo Arabic موحدًا**: واجهة النظام كاملة عبر @font-face (Light/Book/Medium) وملفات PDF عبر التضمين الفعلي (subset مضمّن — يظهر بنفس الشكل على أي جهاز).
5. **إصلاح جذري للعربية في PDF**: أُعيد بناء المحرك على الأساس المنطقي — النص العربي يُمرر كما هو ويتولى fontkit التشكيل والاتجاه، فاختفت مشاكل الحروف المنفصلة/المعكوسة نهائيًا، والنصوص المختلطة (Bayat Al-Akna 101 / A-102 / 150,000) تظهر بترتيبها الصحيح.
6. ملاحظة ترخيص: خط Expo Arabic من 29LT — تأكد من امتلاك ترخيصه لدى الشركة، ويمكن استبدال ملفاته في مجلد fonts بملفاتكم المرخصة وسيستخدمها النظام تلقائيًا (وإن حُذفت يعود للخط البديل المضمّن دون انكسار).

## الجديد في v1.4.0 — بيانات الشركة المركزية والشعار

1. **قسم «بيانات الشركة» في الإعدادات**: تعديل كل شيء من مكان واحد — اسم الشركة (عربي/إنجليزي)، اسم الموقع/النظام، الشعار، الهاتف الرئيسي والهاتف الإضافي والواتساب والبريد والعنوان والموقع الإلكتروني وإنستقرام ورقم السجل التجاري والرقم الضريبي وبيانات إضافية للمستندات والألوان.
2. **اسم الموقع ديناميكي بالكامل**: تغييره من الإعدادات ينعكس فورًا على شاشة الدخول وعنوان النافذة والقائمة الجانبية والتقارير وملفات PDF وأسماء ملفات PDF (بادئة الاسم من اسم الموقع) — بلا نص ثابت في الأكواد.
3. **الشعار مضمَّن فعليًا داخل كل PDF**: رفع واحد من الإعدادات (PNG/JPG، والشفافية مدعومة) يُستخدم تلقائيًا في ترويسة كل صفحة من كل أنواع المستندات والتقارير، مع الحفاظ على نسب الأبعاد بلا تمديد، وتضمين حقيقي داخل الملف (لا مسارات مفقودة) — تم التحقق بأداة pdfimages على كل الأنواع، مع ختم مركزي بديل عند إزالة الشعار.
4. **بيانات التواصل مركزية**: الهواتف/واتساب/بريد/عنوان/س.ت/الرقم الضريبي تُسحب تلقائيًا في تذييلات النظام والطباعة وشريط التواصل الختامي في PDF.
5. **التلقائية التاريخية**: أي تعديل (اسم/رقم/شعار) يسري على كل ملفات PDF الجديدة فورًا، بينما ملفات الأرشيف القديمة تبقى كما أُنشئت (تم التحقق بمقارنة البايتات).
6. **الصلاحية**: تعديل بيانات الشركة يتطلب صلاحية «إدارة بيانات الشركة والهوية» (مدير النظام يملكها تلقائيًا، والمحاسب مثلاً ممنوع افتراضيًا).

1. **البيع المرحلي**: بيع تحت الإنشاء أو بعد الاكتمال، وخصم بقيمة ثابتة أو نسبة مع حساب السعر النهائي تلقائيًا ومنع الخصم الأكبر من السعر.
2. **طريقة الدفع**: كاش / حوالة بنكية / شيك مع رقم الشيك أو مرجع الحوالة، وتحديث المدفوع والمتبقي وحالة السداد تلقائيًا (تتحول الوحدة إلى «مسدد بالكامل» عند إغلاق المبلغ).
3. **إعادة البيع**: عند اكتمال المشروع يُسجَّل قرار المالك (احتفاظ/بيع/إعادة بيع)، وتحوَّل الوحدة إلى «إعادة بيع» بسعر جديد مع حفظ السعر السابق والمالك البائع وكامل السجل التاريخي.
4. **المسوقون والعمولات**: إدارة مسوقين بأكواد، ربطهم بالصفقات، عمولة ثابتة أو نسبة، دفعات عمولات جزئية/كاملة وحالات (غير مدفوعة/جزئية/مدفوعة بالكامل).
5. **البحث المتقدم**: المشروع، الدور، رقم الوحدة، الغرف، الحالة، المرحلة، نطاق السعر والمساحة، وجود خصم، اسم المالك — مع دمج أي عدد من الفلاتر.
6. **مستندات PDF بهوية الشركة**: كشف وحدات، عرض وحدة، سند حجز، سند بيع، وتقارير (مبيعات، دفعات، عمولات، مسوقين، مالي) — عربية RTL بخط أميري وألوان وشعار الشركة، مع أزرار: تصدير PDF / طباعة / حفظ في الأرشيف.
7. **أرشيف المستندات**: كل PDF محفوظ باسم منظم تلقائيًا (مثل `بيات_الأكنة_سند_بيع_SAL-2026-..._2026-08-22.pdf`) مع رقم مرجعي ونوع ومشروع ووحدة وعميل ومنشئه وتاريخه، وبحث وفلترة ومعاينة وتنزيل وطباعة وحذف بالصلاحية.
8. **السجل التاريخي للوحدة**: كل حدث (إضافة، تغيير سعر/حالة، حجز، بيع، إعادة بيع، دفعة، عمولة، إلغاء) موثق بالمستخدم والوقت دون فقدان البيانات القديمة.
9. **لوحة تحكم وتقارير محدثة لحظيًا**: كل عملية تُحدِّث الوحدة والمبيعات والدفعات والعمولات والتقارير تلقائيًا من قاعدة بيانات واحدة.

## بناء ملف Windows

على جهاز Windows مثبت عليه Node.js:

```text
npm install
npm run build:win
```

ينتج ملف التثبيت داخل `release` باسم قريب من:
`Bayat Alakena Real Estate Setup 1.2.0.exe`

(أو استخدم `1-BUILD-WINDOWS.bat`)

## تنبيه مهم بشأن تعدد الأجهزة

هذه النسخة محلية بالكامل. إذا ثُبتت على جهازين فلكل جهاز قاعدة مستقلة. لعمل عدة موظفين على نفس البيانات لحظيًا يلزم إصدار شبكي بقاعدة مركزية.

## الخصائص الأمنية

- كلمات مرور مشفرة وجلسات محدودة وإعادة تحقق من الدور مع كل طلب.
- منع الحجز/البيع المزدوج على مستوى قاعدة البيانات.
- قيود مالية: منع خصم أكبر من السعر، منع دفعة أكبر من المتبقي، إلزام مرجع للشيك/الحوالة.
- سجل عمليات عام + سجل تاريخي لكل وحدة.
- أرشيف مستندات لا يُحذف إلا بصلاحية.
